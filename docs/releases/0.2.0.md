# TracerTool 0.2.0 — assisted terrain editor (prerelease)

TracerTool is an independent desktop editor for drawing and correcting stream
centerlines, ridge crests and slope breaks from a GeoTIFF. Place guide points,
review a terrain-guided preview, edit the line, save a project and export 3D
shapefiles. It runs locally and does not require ArcGIS.

This is a source prerelease for evaluation and contribution. The development
process used substantial AI assistance; see [AI_DISCLOSURE.md](../../AI_DISCLOSURE.md).
The public snapshot excludes private reference terrain and its development
history. Use the synthetic demonstration described in the [README](../../README.md).

## Included workflows

- Elevation colors, hillshade, slope, contours and display settings.
- Stream, ridge, slope-break and manual tracing, with preview before acceptance.
- Smoother feature-aware output and arc-length vertex sampling. Starting
  defaults are 2-cell terrain smoothing, 4-cell line smoothing, 8-cell target
  spacing and 1-cell bend tolerance, with a levee preset. Hard guides and
  terrain/NoData constraints can require shorter edges; actual spacing is shown.
- Vertex move/insert/delete, local corrections, full retracing, split/join,
  reverse, snapping and undo/redo.
- Project persistence, unfinished-draft recovery, backups and source identity
  checks; separate terrain reprojection and explicit export conversion options.
- 3D shapefile and GeoJSON export, retaining source elevations by default.

## Evidence and limits

The initial local 0.2.0 desktop-validation snapshot passed 287 automated tests
on Linux and 287 with Windows Python/Qt under Wine. Publication preparation
adds separate audit regression tests; consult the validation record for the
latest source-check results. Linux native desktop exercises covered
tracing, correction, editing, settings, recovery, save/reopen and export. Both
portable builds passed frozen and clean-extracted smoke checks. The Windows
executable also completed visible select/retrace/preview/cancel interaction
through the Windows Qt plugin under Wine. See [VALIDATION.md](../VALIDATION.md)
for the scope and distinction between those checks.

The first hosted GitHub source run passed 311 tests, dependency checks and the
startup smoke test in each Windows/Linux lane; see the linked validation record.
The public-source preparation expanded the suite to 311 passing tests on
Linux and 303 passing tests with 8 Git-dependent skips under Windows Python/Qt
in Wine. It adds the reproducible synthetic demo and publication checks;
the missing Windows Git checks passed on Linux.

A real clean Windows desktop, QGIS/ArcGIS Pro handoff, independent positional
accuracy and measured operator productivity have not been validated. Illustrative
terrain comparisons are not a surveyed benchmark. The editor suggests geometry;
users must review it before including it in engineering work.

The current scope is one DEM per project. Large inputs may use a disclosed
working grid; rotated/sheared grids are unsupported, and tracing requires a
projected CRS. Full drainage-network extraction, hydrologic conditioning,
connected topology, mosaics and tiled full-resolution analysis remain future
work. XY reprojection does not transform a vertical datum.
